# Контракт API: робот ↔ сервер (v1)

**Статус: черновик v1, 2026-10-15** (шаг 1.1 в `docs/roadmap.md`). Изменения контракта — только через этот файл, затем код в `backend/` и `android-app/`.

## Общее
- Базовый URL: `https://<домен>/v1` (в приложении — `BACKEND_URL` из `secrets.properties`; локально с эмулятора — `http://10.0.2.2:8000/v1`).
- Авторизация: заголовок `Authorization: Bearer <ROBOT_TOKEN>` на всех эндпоинтах, кроме `/health`. Токен — в `.env` сервера и `secrets.properties` робота, не в git.
- Формат: JSON, UTF-8, поля в `snake_case`.
- Языки (`lang`): `ru`, `kk`, `en`. Если `lang` не передан или `null` — сервер определяет язык по тексту вопроса.
- `session_id` — строка 1–64 символа (рекомендуется UUID), генерирует робот на один «разговор» с посетителем (сбрасывается по таймауту бездействия). Нужен для контекста диалога и логов.
- `request_id` — сервер возвращает в каждом ответе и в заголовке `X-Request-Id`, для поиска в логах.
- Ответы сервера уже разбиты на фразы `phrases` ≤ 300 символов (ограничение TTS робота). Робот озвучивает их по очереди, `answer` — полный текст для экрана.

## `GET /v1/health`
Без авторизации. Робот **не отправляет** на `/health` заголовок `Authorization` (используется и для проверки введённого адреса сервера).
```json
200 { "status": "ok", "version": "0.1.0" }
```

## `POST /v1/ask` — вопрос о хабе
Запрос:
```json
{
  "question": "Где проходит регистрация на хакатон?",
  "lang": "ru",
  "session_id": "6f1c…",
  "place_id": "reception"
}
```
| Поле | Тип | Обяз. | Описание |
|---|---|---|---|
| `question` | string, 1–500 символов | да | распознанный текст вопроса |
| `lang` | `ru`/`kk`/`en`/null | нет | язык, если робот его знает |
| `session_id` | string (UUID) | да | |
| `place_id` | string/null | нет | ближайшая точка карты робота (контекст «здесь») |

Ответ `200`:
```json
{
  "request_id": "req_01J…",
  "answer": "Регистрация открыта на 2 этаже, у стойки ресепшена. Возьмите с собой удостоверение.",
  "phrases": ["Регистрация открыта на 2 этаже, у стойки ресепшена.", "Возьмите с собой удостоверение."],
  "lang": "ru",
  "found": true,
  "sources": ["fact:123"]
}
```
- `found: false` — в базе нет ответа; `answer` содержит вежливый отказ («обратитесь на ресепшен») на языке вопроса. Вопрос логируется как «без ответа».
- `sources` — id фактов базы, использованных в ответе (для отладки, на экран не выводятся).

### Стриминг (шаг 4.4)
Тот же запрос с заголовком `Accept: text/event-stream` → SSE:
```
event: phrase
data: {"text": "Регистрация открыта на 2 этаже, у стойки ресепшена."}

event: phrase
data: {"text": "Возьмите с собой удостоверение."}

event: done
data: {"request_id": "req_01J…", "lang": "ru", "found": true, "sources": ["fact:123"]}
```
Ошибки авторизации и валидации (401/400/413/429) приходят обычным HTTP-ответом до начала потока; событием `event: error` (тело как в разделе «Ошибки») приходят только ошибки во время генерации (LLM). Робот начинает говорить по первой `phrase`.

Посетитель перебил робота → робот закрывает соединение. Сервер перестаёт слушать модель и пишет в историю вопрос и уже
отправленные фразы с `interrupted: true` (см. «История разговора»). Ответ, оборванный после `done`, считается полным.

## `POST /v1/look` — «Что это?»
`multipart/form-data`:
| Часть | Тип | Обяз. | Описание |
|---|---|---|---|
| `image` | `image/jpeg`, ≤ 1 МБ (обычно 640×480, q≈80); не JPEG → 400 | да | кадр с камеры |
| `meta` | JSON-строка | да | `{"question": "Что это за комната?", "lang": "ru", "session_id": "…", "place_id": "coworking_2f"}` |

`question` в `meta` — необязательный (по умолчанию «что это / где я»). Ответ — **тот же формат, что у `/ask`**. Кадр не сохраняется на сервере и не пишется в логи.

## `GET /v1/places` — точки карты и синонимы
Для сопоставления «кафешка» → точка карты и офлайн-кеша на роботе (шаги 5.3, 5.7). Поддерживает `ETag` / `If-None-Match` → `304`.
```json
{
  "places": [
    {
      "id": "cafe",
      "map_name": "Кафе",
      "names": { "ru": "Кафе", "kk": "Кафе", "en": "Cafe" },
      "synonyms": ["кафешка", "асхана", "столовая", "coffee"],
      "description": { "ru": "Кафе на 1 этаже…", "kk": "…", "en": "…" }
    }
  ]
}
```
`map_name` — имя точки ровно как в `getPlaceList` робота.

## `GET /v1/quick-questions?lang=ru` — кнопки частых вопросов
```json
{ "items": [ { "id": "wifi", "text": "Какой пароль от Wi-Fi?" } ] }
```
Нажатие кнопки = `POST /v1/ask`, где `question` = `items[].text`.

## `POST /v1/chat` — агентский чат (разговор с памятью и действиями)
Новый основной путь разговора (ADR `docs/decisions/0001-agent-chat-stack.md`). Агент на сервере сам решает: ответить из базы
знаний, уточнить, показать дорогу или проводить, посмотреть камерой. Помнит разговор в рамках `session_id`.
`/v1/ask` и локальные правила робота остаются **запасным путём** (нет сети, `/v1/chat` вернул ошибку или не ответил вовремя).

Ответ — **только SSE** (`Accept: text/event-stream`). Тело запроса ≤ 16 КБ, rate limit — общий с `/ask` и `/look`.

Запрос:
```json
{
  "session_id": "6f1c…",
  "text": "Где тут можно поработать?",
  "lang": "ru",
  "input": "voice",
  "event": null,
  "robot_state": { "nearest_place_id": "reception", "navigating": false }
}
```
| Поле | Тип | Обяз. | Описание |
|---|---|---|---|
| `session_id` | string 1–64 | да | один посетитель = одна сессия; новая — когда посетитель ушёл (заставка) |
| `text` | string 0–500 | да* | реплика посетителя. Пусто допустимо только с `event` |
| `lang` | `ru`/`kk`/`en`/null | нет | язык экрана/распознавания; агент отвечает на языке реплики |
| `input` | `voice`/`text`/`button` | нет | откуда пришла реплика (для аналитики) |
| `event` | `visitor_arrived`/null | нет | `visitor_arrived` — к роботу подошёл человек: агент коротко здоровается и предлагает помощь (`text` пустой) |
| `robot_state.nearest_place_id` | string/null | нет | ближайшая точка карты («здесь») |
| `robot_state.navigating` | bool | нет | робот сейчас ведёт посетителя |

SSE-события (по порядку, `turn` — всегда первое, `done` или `error` — всегда последнее):
| `event:` | `data` | Что делает робот |
|---|---|---|
| `turn` | `{"turn_id": "trn_…", "request_id": "req_…"}` | запоминает `turn_id` (нужен для `look`) |
| `emotion` | `{"name": "happy"}` — `neutral`/`happy`/`thinking`/`surprised`/`sad`/`excited` | меняет выражение лица (тамагочи) |
| `phrase` | `{"text": "Есть коворкинг на втором этаже."}` | озвучивает и показывает (≤ 300 символов) |
| `action` | `{"name": "where_is", "args": {"place_id": "coworking_2f", "map_name": "coworking"}}` | выполняет действие (см. ниже) |
| `done` | `{"request_id": "req_…", "lang": "ru", "tools": ["find_place"]}` | конец хода |
| `error` | общий формат ошибок | фраза ошибки, дальше — запасной путь |

Действия (`action`) — выполняет **робот**, по своей карте:
| `name` | `args` | Что делает робот |
|---|---|---|
| `where_is` | `place_id`, `map_name` | считает направление и расстояние от своей позиции и **сам озвучивает** («справа от вас, метров 15») — как сейчас офлайн |
| `guide_to` | `place_id`, `map_name` | едет к точке (навигация, фразы в пути). Агент отдаёт его **только после согласия** посетителя в разговоре |
| `stop` | — | останавливает навигацию |
| `look` | — | снимает кадр и отправляет `POST /v1/chat/{turn_id}/frame` **в течение 8 с**; агент продолжает этот же поток с описанием |

### `POST /v1/chat/{turn_id}/frame` — кадр по запросу агента
`multipart/form-data`, часть `image` (`image/jpeg`, ≤ 1 МБ, как у `/look`). Ответ `204`. Кадр не сохраняется. Нет такого
хода / ход уже закрыт / кадр не запрашивался → `404`. Не пришёл за 8 с — агент отвечает без кадра.

Ограничения сервера: не больше **3 вызовов тулов** за ход; первая фраза — как можно раньше (цель ≤ 3 с); весь ход ≤ 20 с
(с `look` — ≤ 30 с); ответ ≤ 4 фраз / 600 символов; память — последние ~10 сообщений сессии (таблица `messages`).
Тулы агента на сервере: `search_knowledge`, `find_place` (место по смыслу: «где помыть руки» → `restroom`), `look`.
Робот обрывает поток (посетитель перебил) → сервер останавливает агента, ход пишется с `interrupted: true`.

Таймауты робота: первое событие (`turn`) ≤ 4 с, первая `phrase` ≤ 8 с — иначе запасной путь (`/v1/ask`).

## История разговора (чат на экране)
Чат на экране робот ведёт **сам**: сообщения появляются сразу, без ожидания сервера. Сервер хранит ту же историю, чтобы
восстановить чат (пересоздание экрана, перезапуск приложения) и чтобы в логе были все вопросы, включая локальные ответы
и оборванные. Порядок работы — [`frontend-chat.md`](frontend-chat.md).

### `GET /v1/sessions/{session_id}/messages?limit=50` — история разговора
`limit` — сколько последних обменов «вопрос → ответ» вернуть, 1–200 (по умолчанию 50). Сообщения идут по времени,
старые первыми; на каждый обмен два сообщения — `user` и `assistant`. Нет такого разговора → пустой список.
```json
{
  "session_id": "6f1c…",
  "messages": [
    { "id": "req_01J…:q", "role": "user", "kind": "ask", "text": "Какой пароль от Wi-Fi?", "lang": "ru",
      "created_at": "2026-10-21T09:15:02.481+00:00", "request_id": "req_01J…", "found": null, "interrupted": null },
    { "id": "req_01J…:a", "role": "assistant", "kind": "ask", "text": "Гостевая сеть называется AstanaHub-Guest.",
      "lang": "ru", "created_at": "2026-10-21T09:15:02.481+00:00", "request_id": "req_01J…",
      "found": true, "interrupted": false }
  ]
}
```
| Поле | Описание |
|---|---|
| `id` | `<request_id>:q` для вопроса, `<request_id>:a` для ответа — стабильный ключ для списка на экране |
| `kind` | `ask`, `look` — ответил сервер; `where_is`, `guide_to`, `where_am_i` — робот ответил сам (см. POST ниже) |
| `found` | у ответа: `false` — в базе ответа нет (вежливый отказ); у вопроса `null` |
| `interrupted` | у ответа: `true` — посетитель перебил робота, `text` содержит только то, что успело уйти роботу |

`interrupted: true` сервер ставит сам, когда робот обрывает SSE-поток `/ask` до события `done`. Ответы в JSON-режиме
сервер отдаёт целиком, поэтому прерванную озвучку такого ответа он не видит.

### `POST /v1/sessions/{session_id}/messages` — ответ, который робот дал без сервера
«Где X?», «Проводи», «Где я?» робот отвечает сам (по карте, без сети). Чтобы эти обмены были в истории и в логе,
робот присылает их сюда. Ответ не нужен для работы робота: ошибку можно только залогировать, повтор не обязателен.
```json
{ "kind": "where_is", "question": "Где кафе?", "answer": "Кафе справа от вас, метров 15.", "lang": "ru",
  "place_id": "cafe", "found": true, "interrupted": false }
```
| Поле | Тип | Обяз. | Описание |
|---|---|---|---|
| `kind` | `where_is` / `guide_to` / `where_am_i` | да | какое локальное намерение сработало |
| `question` | string, 1–500 | да | вопрос посетителя |
| `answer` | string, 1–2000 | да | что робот ответил (сказал и показал) |
| `lang` | `ru`/`kk`/`en` | да | язык ответа |
| `place_id` | string/null | нет | точка карты, о которой шла речь |
| `found` | bool, по умолчанию `true` | нет | `false` — место не нашли («не знаю такого места») |
| `interrupted` | bool, по умолчанию `false` | нет | посетитель перебил робота на этом ответе |

Ответ `201`: `{ "request_id": "req_…" }`. Ошибки — общий формат (неверное тело → `400`).

## Голос через сервер (вариант B из `docs/stack.md`, на случай если встроенный ASR/TTS робота не умеет RU/KZ)
Провайдер на сервере — за интерфейсом `SpeechProvider` (по умолчанию Yandex SpeechKit: `ru-RU`, `kk-KZ`, `en-US`); ключи только на сервере. Робот: запись с микрофона → `/stt` → показать текст → `/ask` → для каждой фразы `/tts` → проиграть (следующую фразу запрашивать, пока играет текущая).

### `POST /v1/stt` — распознать речь
`multipart/form-data`:
| Часть | Тип | Обяз. | Описание |
|---|---|---|---|
| `audio` | `audio/wav` (PCM 16-bit, mono, 16 кГц), ≤ 15 с, ≤ 600 КБ | да | фраза посетителя (робот сам обрезает тишину по VAD) |
| `meta` | JSON-строка | да | `{"lang": "kk" \| "ru" \| "en" \| null, "session_id": "…"}` |

`lang = null` → сервер пробует распознать с автоопределением языка (ru/kk/en). Ответ `200`:
```json
{ "request_id": "req_…", "text": "Асхана қай жерде?", "lang": "kk", "confidence": 0.92 }
```
`confidence` может быть `null` (Yandex API v1 его не возвращает).
Пустая речь/тишина → `200` с `"text": ""` (робот ничего не отправляет в `/ask`).

### `POST /v1/tts` — синтез фразы
Запрос: `{"text": "Асхана бірінші қабатта.", "lang": "kk"}` (`text` ≤ 300 символов — одна фраза из `phrases`).
Ответ `200`: тело `audio/mpeg` (MP3, моно), заголовок `X-Request-Id`. Сервер кеширует аудио по `(lang, text)`.
Во всех ответах `/tts` (и `200`, и ошибки провайдера `503`/`504`) — заголовок `X-Speech-Provider: <имя>` (`elevenlabs`, `yandex`, `fake`); при `fake` тело — тишина-заглушка, робот озвучивает фразу встроенным TTS.

### `WS /v1/stt/stream` — live-распознавание (текст, пока посетитель говорит)
WebSocket вместо `POST /v1/stt`: звук уходит на сервер по ходу речи, текст приходит частями, финальный —
через доли секунды после конца фразы (а не через 2–3 с после загрузки WAV целиком).

Подключение: `ws(s)://<host>/v1/stt/stream?session_id=<id>&lang=ru|kk|en` + заголовок `Authorization: Bearer <token>`.
`lang` необязателен, но **передавайте текущий язык экрана**: без него сервер определяет язык сам, это медленнее
и для казахского ненадёжно. Один WebSocket = одна фраза.

Клиент → сервер:
| Кадр | Что это |
|---|---|
| бинарный | PCM 16-bit little-endian, mono, 16 кГц, без WAV-заголовка; чётное число байт, ≤ 64 КБ. Рекомендуется 100 мс = 3200 байт |
| `{"type": "end"}` | посетитель закончил (VAD приложения, кнопка). Необязателен: сервер сам находит конец фразы |
| `{"type": "cancel"}` | отмена (посетитель нажал «Стоп», ушёл); финального текста не будет |

Сервер → клиент (текстовые JSON-кадры):
```json
{"type": "ready",   "request_id": "req_…", "provider": "elevenlabs-realtime"}
{"type": "partial", "text": "Где здесь"}
{"type": "partial", "text": "Где здесь можно выпить кофе"}
{"type": "final",   "request_id": "req_…", "text": "Где здесь можно выпить кофе?", "lang": "ru"}
{"type": "error",   "code": "speech_unavailable" | "timeout" | "bad_request", "message": "…"}
```
- `partial` — текст фразы целиком на данный момент (не прирост): показывать на экране, заменяя предыдущий.
- `final` — ровно один, после него сервер закрывает соединение (код 1000). Пустой `text` — речи не было,
  в `/ask` ничего не отправлять. `final.text` → `/v1/ask` так же, как ответ `/v1/stt`.
- Сервер сам закрывает фразу: после паузы ~0,8 с (ElevenLabs VAD), через 15 с звука, через 8 с без речи,
  если звук перестал приходить.
- `error` → затем закрытие 1011 (1008 для `bad_request`). Без токена — закрытие 1008 до `ready`;
  rate limit — закрытие 1013 (лимит общий с `/stt` и `/tts`, одно подключение = один запрос).
- `provider`: `elevenlabs-realtime` — настоящий live с `partial`; `buffered:<stt>` — ключа ElevenLabs нет или
  realtime недоступен: `partial` не будет, сервер распознаёт фразу целиком после `end` (нужен VAD приложения).

Таймауты робота: `/stt` — 6 с, `/tts` — 5 с. Rate limit для `/stt` и `/tts` — отдельный, 120 запросов/мин на токен (один вопрос = 1 stt + 1 ask + N tts). В `/tts` поле `lang` необязательно (определяется по тексту). Ошибки — общий формат; при недоступности провайдера — `503 speech_unavailable` (робот показывает текст на экране без озвучки и говорит встроенным TTS, если он есть).

## Ошибки
Любой не-2xx ответ:
```json
{ "error": { "code": "llm_unavailable", "message": "…" }, "request_id": "req_…" }
```
| HTTP | `code` | Что делает робот |
|---|---|---|
| 400 | `bad_request` | фраза «не расслышал, повторите» |
| 401 | `unauthorized` | лог + фраза «нет связи с сервером» |
| 413 | `payload_too_large` | пересжать кадр и повторить 1 раз |
| 429 | `rate_limited` | фраза «секунду…», повтор через `Retry-After` |
| 503 | `llm_unavailable` | фраза «нет связи», навигация продолжает работать |
| 503 | `speech_unavailable` | ответ только текстом на экране |
| 504 | `timeout` | то же |
| 404/405 | `not_found` / `method_not_allowed` | ошибка клиента, лог |
| 500 | `internal_error` | фраза «нет связи» |

Готовые фразы ошибок на RU/KZ/EN хранятся **на роботе** (работают без сети).

## Таймауты и лимиты
- Робот: `/ask` — 8 с, `/look` — 12 с, `/places` и `/quick-questions` — 5 с; ретраев нет (кроме 413/429).
- Сервер: p95 `/ask` ≤ 2 с до первой фразы (шаг 3.9).
- Rate limit на токен: `/ask`, `/look` и `/sessions/…` — 30/мин; `/stt`, `/tts` и `WS /stt/stream` — 120/мин; `/places` и `/quick-questions` — отдельный бакет 60/мин (их опрос не должен съедать лимит вопросов).
- Размер тела (проверяется **до** чтения и до авторизации; превышение → 413 без разбора тела): `/ask` ≤ 16 КБ; `/look` ≤ 1 МБ + 64 КБ; `/stt` ≤ 600 КБ + 64 КБ; `/tts` ≤ 4 КБ. Запрос без валидного токена отклоняется 401 до чтения тела.
- Длина ответа ограничена сервером: не больше 4 фраз и 600 символов в `answer` (робот не должен говорить минутами); в SSE после лимита фразы больше не отправляются.
- `/docs`, `/redoc`, `/openapi.json` в продакшене не отдаются (404); схема — в `backend/openapi.json`.
