# Задачи Astana Hub Robot

Список на 2026-10-23. Исполнители пока не назначены. У каждой задачи — критерий готовности (DoD).

## 🔥 Срочно — мешает работе робота

### 1. Стабильные ответы ИИ (ошибки Gemini 503)
Бесплатный ключ Gemini в часы нагрузки отвечает 503: голос срывается с «нет связи», ответы идут 4–6 с.
- Включить биллинг для текущего ключа Gemini **или** перейти на OpenRouter (поддержка есть в ветке `voice/live-stt-openrouter-elevenlabs`).
- **DoD:** 20 вопросов подряд на сервере без 503/504, ответ ≤ 3 с.

### 2. Точки карты робота в базу знаний
На карте точки называются `restroom`, `cafe` и т. д., а в базе сервера сейчас 6 выдуманных мест — «где туалет» не находит `restroom`.
- Снять список точек: экран диагностики → `getPlaceList`.
- Для каждой точки завести в `places`: `map_name` (ровно как на карте), названия RU/KZ/EN, синонимы, описание, этаж. Выдуманные места выключить.
- **DoD:** «Где туалет?», «Дәретхана қайда?», «Where is the restroom?» → направление и расстояние до `restroom`.

### 3. Карта и локализация робота
После записи карты робот повторяет «не толкайте меня»; после удаления карты перестал, но без карты не работают «где X» и «проводи».
- Вернуть карту, отметить именованные точки и зарядку, привязать робота к карте (зарядная станция или «текущая позиция»).
- Передвигать робота только с нажатой кнопкой аварийной остановки (E-stop), потом заново локализовать.
- **DoD:** робот стоит спокойно, `getPosition` в диагностике отдаёт координаты, «проводи до кафе» — робот доезжает.

### 4. Влить ветку `voice/live-stt-openrouter-elevenlabs`
Живое распознавание речи по WebSocket, история чата, пометка «перебил», провайдер OpenRouter, голос ElevenLabs. Тесты зелёные (backend 376, Android 180/191), конфликтов с `main` нет.
- Просмотреть изменения контракта (`docs/api-contract.md`) и миграцию `0002`, слить через PR, задеплоить.
- **DoD:** на сервере `WS /v1/stt/stream` работает через Caddy, текст приходит, пока посетитель говорит.

## 🖥 Сервер

### 5. Доступ к серверу только по ключам
- Сменить временные пароли; собрать публичные SSH-ключи всех админов.
- `PasswordAuthentication no`, затем `PermitRootLogin no`.
- **DoD:** вход по паролю отклоняется, все админы входят по своим ключам, `sudo` работает.

### 6. Бэкапы базы вне сервера
Сейчас бэкапов вне сервера нет.
- Ежедневный `pg_dump` (скрипт `infra/scripts/backup.sh`) + копия во внешнее хранилище (Storage Box / S3), хранение 14+ дней.
- **DoD:** бэкап появляется каждый день вне сервера; восстановление в чистую базу проверено один раз и описано.

### 7. Мониторинг и алерты
- Внешняя проверка `https://…/v1/health` каждую минуту, алерт в Telegram при падении.
- Алерты: заполненность диска > 80 %, бэкап не сделан, сертификат истекает.
- **DoD:** остановили `api` → алерт пришёл за ≤ 2 мин.

### 8. Автодеплой из GitHub
- Пользователь `deploy` на сервере, ограниченный SSH-ключ для CI (forced command), секреты в GitHub.
- Деплой по тегу `v*` только после зелёных тестов, автооткат при неудачном старте.
- **DoD:** `git tag v0.2.0 && git push --tags` → новая версия на сервере без ручных команд; сломанный релиз откатывается сам.

### 9. Документация деплоя
- Дописать в `docs/server-setup.md`: как устроен деплой проекта, где `.env`, как обновлять, откатывать, смотреть логи.
- **DoD:** новый человек по документу обновляет сервер без подсказок.

## 🤖 Функции

### 10. Агентский чат
Стек утверждён: OpenAI Agents SDK + Claude Haiku 5.5 + голос ElevenLabs (`docs/decisions/0001-agent-chat-stack.md`).
- Зафиксировать `/v1/chat` в контракте; агент с тулами (база знаний, «где X», «проводи», камера), память в `sessions`/`messages`, защита от prompt injection; трассировка в OpenAI выключена.
- Робот выполняет команды агента (проводить, снять кадр, показать на экране).
- Нужны ключи: Anthropic, ElevenLabs.
- **DoD:** диалог «Где поработать?» → уточняющий вопрос → «Проводить?» → робот едет; первая фраза ≤ 3 с.

### 11. Векторный поиск по базе знаний (RAG)
Таблица `kb_chunks` и индексы уже есть, данных и поиска нет.
- Эмбеддинги (Gemini), заполнение `kb_chunks`, гибридный поиск (по смыслу + по словам), загрузка длинных документов (Google Drive).
- **DoD:** вопрос по тексту из длинного документа (программа, правила) получает верный ответ со ссылкой на источник.

### 12. Настоящая база знаний
Сейчас 13 фактов-заглушек.
- Google-таблица с вкладками «Факты», «Места», «Кнопки», «Мероприятия» (шаблоны: `backend/knowledge/sheet_template/`), синк на сервер (`KNOWLEDGE_SHEET_ID`).
- **DoD:** сотрудник хаба добавил факт в таблицу → через ≤ 5 мин робот отвечает по нему.

### 13. Админка базы знаний
- REST для правки мест, фактов, кнопок, мероприятий (`/v1/admin/*`, отдельный админ-токен) + простая веб-панель.
- **DoD:** место с синонимами добавляется в браузере и сразу находится роботом.

### 14. Робот «просыпается», когда подходит человек
Сейчас робот ведёт себя как планшет: ждёт касания.
- `PersonApi.registerPersonListener` + `getAllPersons(maxDistance)`: человек в 1–3 м → выход из заставки, приветствие на текущем языке, экран переходит в режим разговора.
- Анти-спам: не здороваться повторно с тем же человеком (id из `Person`), не реагировать на проходящих мимо (порог расстояния и времени).
- Робот ушёл в заставку → снова ждёт человека.
- **DoD:** подошёл человек → за ≤ 1.5 с робот выходит из заставки и здоровается; прошёл мимо в 4 м — без реакции; один и тот же человек — одно приветствие.

### 15. Голова поворачивается к человеку
- `startFocusFollow(faceId, …)`: голова следит за лицом собеседника, корпус доворачивается; при потере человека — `resetHead` в исходное положение.
- Лёгкие движения головы во время ответа (кивок, поворот) через `moveHead` — чтобы робот выглядел живым, а не планшетом.
- Не конфликтовать с навигацией (во время «проводи» слежение выключено — одно устройство нельзя вести двумя API).
- **DoD:** человек отходит в сторону — голова следует за ним; ушёл — голова возвращается; во время навигации слежения нет.

### 16. Тамагочи — живой персонаж на экране
Робот как персонаж с характером, а не планшет с меню.
- Лицо на экране (уже есть в MVP-интерфейсе: эмоции) превратить в персонажа: настроение и реакции на события (подошёл человек, похвалили, долго один, низкий заряд, ночь), анимации в простое.
- Состояние персонажа хранится и меняется со временем (сервер: таблица или поля в Postgres).
- Концепцию и механику согласовать (что «радует» и «огорчает» персонажа, как это видит посетитель).
- **DoD:** описанная концепция + на экране персонаж меняет настроение минимум по 4 событиям, в простое — анимация.

### 17. Release-сборка и скорость приложения
- Подписанный release-APK (R8), для робота — release вместо debug.
- Потоковый ответ в приложении (озвучка с первой фразы), если не покрыт веткой из задачи 4.
- Токен на каждого робота (таблица `robots`) с отзывом; CI собирает вариант `robotos`.
- **DoD:** на роботе стоит подписанный release, время до первого звука ≤ 2.5 с.
