# Дизайн-система нового интерфейса робота

Бриф — `BRIEF.md`. Здесь — решения, токены, движок лица с числами и как всё проверить на эмуляторе.
Код: `android-app/app/src/main/java/kz/astanahub/robot/ui/{design,motion,face}/`.

## 1. Стек

**UI-слой — Jetpack Compose (BOM 2026.06.01 = Compose 1.11.4), лицо — свой движок + Canvas.**

Почему Compose:
- экран 2 (M3) — жест с физикой, морфинг лица в мини-глаза, чат, плитки, материалы: в Compose это
  `Animatable` с передачей скорости, `graphicsLayer` (transform/alpha на GPU), `pointerInput` с параллельным
  распознаванием жестов — без ручной возни с View-иерархией;
- бизнес-логика не меняется: Compose подключается к тем же `MainViewModel`/`StateFlow`;
- Compose 1.11 работает с minSdk 26, compileSdk 36, AGP 8.13 (1.12+ требует compileSdk 37 и AGP 9.1 — не берём).

Почему лицо — не Compose-анимации, а свой движок:
- ~48 параметров с пружинами, которые меняют цель каждый кадр (звук, взгляд): 48 `Animatable` с корутинами —
  лишние аллокации и диспетчеризация на слабом железе;
- кадр лица идёт по vsync (`Choreographer`) в `Modifier.Node` (`FaceSurface.kt`): `engine.update(frameTime)` →
  `invalidateDraw()` — перерисовывается только фаза отрисовки узла, без рекомпозиции и snapshot-записей;
- движок — чистый Kotlin (`FaceEngine`, `FaceDirector`, `FaceLife`, `FaceGeometry`): детерминированные JVM-тесты
  без реального времени, проверка «ноль аллокаций в кадре».

Прежний экран (XML + `RobotFaceView`) пока живёт под лицом — это «экран 2» до M3 (см. § 8).

## 3. Шрифт и типографика

**Inter 4.1** (релиз 4.1, в name-таблице файла — Version 4.001; OFL, `licenses/Inter-OFL.txt`) — гротеск, задуманный для экранов, близкий к SF Pro по пропорциям и
ритму; полная кириллица, **все казахские буквы** (ә ғ қ ң ө ұ ү һ і — проверено по cmap всех начертаний),
знаки ₸ № « » — …. Вшит в APK (`res/font/inter_{regular,medium,semibold,bold}.ttf`) подмножеством
Latin + Latin-1/Ext-A + кириллица U+0400–04FF + пунктуация/стрелки: ~150 КБ на начертание вместо ~400.
Альтернативы: Golos/Onest (хуже хинтинг на 1080p), системный Roboto (нет гарантии казахских глифов на прошивке
робота), Nunito (прежний, «детский» скруглённый — не Apple-стиль).

`HubType` (киоск 1600 dp по ширине, читают с ~1 м): размер, жирность, интерлиньяж — набором; трекинг зависит
от размера (крупное — плотнее).

| Стиль | Размер / строка | Жирность | Трекинг |
|---|---|---|---|
| Display | 72 / 78 sp | SemiBold | −0.025 em |
| Title | 44 / 50 | SemiBold | −0.015 em |
| Headline | 34 / 41 | SemiBold | −0.01 em |
| Body | 28 / 38 | Regular | 0 |
| Callout | 24 / 32 | Medium | 0 |

Отступы — сетка 8 dp (`HubSpace`): 8, 16, 24, 32, 48, 64. Касание — минимум 44 dp, на киоске 64 dp.

## 4. Движение

Пружины Apple: **dampingRatio ζ** (1 — без перелёта) и **response** (с). Перевод (масса 1):
`stiffness = (2π / response)²`, `damping = 4π·ζ / response` (`ui/motion/Spring.kt`, тест сверяет формулы).
Шаг пружины — **точное аналитическое решение** осциллятора (не Эйлер): устойчив при любом dt, детерминирован,
смена цели сохраняет значение и скорость → любая анимация прерываема без скачка.

| Токен (`HubMotion`) | ζ | response | stiffness | Где |
|---|---|---|---|---|
| Default | 1.0 | 0.35 | 322 | появление, смена состояния |
| Snappy | 1.0 | 0.25 | 632 | мелкие элементы |
| Gentle | 1.0 | 0.50 | 158 | крупные поверхности (слой лица) |
| Momentum | 0.8 | 0.35 | 322 | только после жеста с импульсом |
| Press | 1.0 | 0.12 | 2742 | нажатие: scale 0.97 на touch-down |

Уменьшение движения: если системные анимации выключены (`ValueAnimator.areAnimatorsEnabled() == false`),
лицо работает без толчков «тела», покачиваний и прыжков, амплитуды «жизни» × 0.4; смена выражений
(это информация о состоянии) и моргание остаются.

## 5. Лицо

### 5.1 Холст и форма

Виртуальный холст **1400 × 790 единиц**, центр — (0, 0), y вниз; вписывается в экран
(`u = min(w/1400, h/790)`, на 1920 × 1080 — 1 ед. ≈ 1.37 px). Всё лицо — «голова»: сдвиг, наклон, масштаб,
сплющивание поверх.

Глаз и рот — одна фигура «линза»: два угла и вершины верхней и нижней дуги, между ними — четверти эллипса
(кубические Безье, κ = 0.5523). Фигура рисуется **заливкой и штрихом 26 ед. со скруглением**: если дуги совпали,
заливки нет и остаётся ровный штрих — так открытый глаз, закрытый глаз-линия, глаз-дуга «∩» (радость), «∪» (сон),
рот-штрих, рот «D» и «o» — **одна непрерывная форма**, морфятся друг в друга без подмены картинок.
Брови — квадратичная кривая (штрих 26 ед.). Веко (прищур, грусть, решимость) — чёрная кромка поверх глаза под углом.
Украшения: «?» (обводится штрихом по мере появления, `PathMeasure`), «///» румянец, капля, «z z z».

Свечение — радиальный градиент под глазами (1.65 × размера глаза) и под штрихами (эллипс +30 ед.):
мягкое пятно, без размытия — одинаково на всех версиях Android (RenderEffect только с API 31).

| Константа (`FaceLayout`) | Значение |
|---|---|
| центры глаз | x = ±250, y = −40 |
| ход взгляда при |gaze| = 1 | x ± 95, y ± 62 |
| бровь над верхом глаза | 64 (+ подъём) |
| рот | y = 205 |
| штрих | 26 |
| перспектива взгляда вбок | дальний глаз −7 % |
| брови / рот следуют за взглядом | 70 % / 45 % |
| голова доворачивается за взглядом | 34 ед. и 1.5° на |gaze| = 1 |
| полное раскрытие рта | 72 |

| Группа | Параметры | Пружина ζ / response |
|---|---|---|
| Форма | глаза (полуширина, полувысота, открытость L/R, «щёки» L/R, дуга закрытого, веко L/R и угол, расстояние, высота, асимметрия), брови (подъём L/R, наклон L/R, изгиб, длина), рот (ширина, уголки, округлость, перекос, сдвиг) | 1.0 / 0.30 |
| Взгляд | gazeX, gazeY | 1.0 / 0.16 (саккада без «строба»: ≤ ~45 px за кадр на полном ходе) |
| Голова | сдвиг, наклон, масштаб, доворот за взглядом | 1.0 / 0.55 (глаза ведут, голова догоняет) |
| Рот (выражение) | раскрытие | 1.0 / 0.20 |
| Украшения | «?», румянец, капля, яркость бровей | 1.0 / 0.32 |
| Медленные | свечение, дыхание (амплитуда, частота), микродвижения, «z» | 1.0 / 0.90 |
| Реакция на звук | коэффициенты «говорит» / «слушает» | 1.0 / 0.22 |
| «Тело» | сплющивание, надувание глаз | 0.55 / 0.42 — двигается только толчками |
| Покачивание «нет» | shake | 0.25 / 0.32 — 2–3 качания от толчка |

Темп по состояниям (множитель response формы, рта, головы): зевок ×2.4, сон ×3.2 (веки тяжелеют), поглаживание
×1.4, пробуждение ×0.8. Отскок (ζ < 1) — только у «тела», и только от толчка-события (вход в радость, удивление,
пробуждение, ошибка) — это «жест с импульсом» персонажа; морфинг формы всегда без перелёта.

### 5.4 Эмоции сервера (`emotion`) поверх состояния

`neutral` — ничего; остальные — частичные наложения (рот «говорит» сам: раскрытие и коэффициенты звука эмоция
не трогает).

| Эмоция | Наложение |
|---|---|
| happy | «щёки» 0.75, брови +12 / изгиб 13, рот 80 / +28, румянец 0.2, свечение 1.0; толчок |
| excited | «щёки» 0.85, глаза 66 × 92, брови +18, рот 86 / +32, румянец 0.35; толчок |
| surprised | глаза 70 × 106, брови +26 / изгиб 16, рот «о» 34 / 0.4 (пока говорит — раскрытие от речи); надувание глаз |
| sad | веко 0.24 под 16°, брови +4 / 14°, рот 50 / −14, голова 6 вниз, свечение 0.5 |
| thinking | взгляд (0.45, −0.55), правая бровь +16, рот сдвиг 18 / перекос 5 |

Сила наложения: покой 1.0, говорит 0.85, слушает 0.6, ведёт и смотрит 0.3 (в поездке главное — «целеустремлённо»),
во «встроенных» выражениях (думает, ошибка, сон, реакции…) — 0. Эмоция держится 6 с (MainViewModel), потом лицо
спокойное. `thinking` в покое включает и взгляд «думающего» (вверх-вправо ↔ вверх-влево).

Растерянность «не знаю» передаёт сервер эмоцией (`sad`); `found: false` реакцией не считается — так помечены и
ответы из общих знаний (`ANSWER_MODE=open`), и шум.

### 5.5 Машина состояний (`FaceDirector`)

Приоритет (сверху сильнее):
1. отладочное принудительное состояние;
2. сон: `mode == SLEEP` → **YAWN 2.4 с → SLEEP** (если приложение стартовало уже во сне — сразу SLEEP);
3. пробуждение: **WAKE 0.9 с**;
4. поглаживание (+0.7 с после) — M2;
5. реакция (`FaceCue`, держится свой срок; обрывается, если робот начал думать / смотреть / поехал или посетитель
   заговорил; речь робота реакцию не обрывает — лицо «огорчённо говорит»);
6. поездка → TRAVEL; думает → THINKING; смотрит → LOOKING; говорит → SPEAKING;
7. покой/слушает + посетитель говорит (промежуточный текст ASR или **VAD**) → LISTENING;
8. иначе IDLE.

«Посетитель говорит» — только по VAD, не по громкости (громкость — лишь сила реакции; гул зала «слушаю» не включает):
адаптивный VAD приложения (`EnergyVad` в `MicRecorder`, `LiveEndpointer` в live STT — порог по шумовому фону) и
серверный `user_speaking` … `user_final` в live. VAD держится 500 мс после последнего «говорит» — паузы между словами
не роняют «слушаю». Фаза LISTENING без голоса (на роботе микрофон открыт почти всегда) — это покой. «Встрепенуться»
(толчок глаз) — только когда пошёл текст посетителя, не на каждое включение VAD.

| Реакция (`FaceCue`) | Выражение | Срок |
|---|---|---|
| ERROR, TRIP_FAILED | ERROR | 2.6 с |
| CONFUSED | CONFUSED | 2.8 с |
| GREET | EXCITED | 2.0 с |
| ARRIVED | HAPPY | 2.2 с |
| TRIP_CANCELLED | ACK | 1.4 с |
| SURPRISE | SURPRISED | 1.3 с |

### 5.6 «Жизнь» (`FaceLife`)

- **Моргание**: каждые 2–6 с (случайно), 20 % — двойное (второе через 240 мс); кривая 200 мс: закрытие 70 мс,
  пауза 20 мс, открытие 110 мс; при большой саккаде — моргание с вероятностью 30 %; говорит — чаще (×0.75),
  думает ×1.4, смотрит ×1.6; во сне, при зевке и поглаживании — нет. Брови при моргании опускаются на 3 ед.
- **Взгляд** по состоянию: покой — 50 % рядом с центром, 50 % — по сторонам (|x| 0.35–0.8), часто с возвратом
  через 0.8–1.6 с, раз в 1.8–4.5 с; слушает / радуется — смотрит на собеседника, микросаккады ±0.06 раз в 0.5–1.4 с;
  думает — вверх-вправо ↔ вверх-влево раз в 1.2–2.4 с; говорит — на собеседника, в 35 % коротко отводит взгляд;
  ведёт — по ходу, в 30 % оглядывается на посетителя на 0.8 с; смотрит в камеру — из стороны в сторону.
  Саккада — пружина взгляда (0.16 с), голова догоняет медленнее (0.55 с); глаза на быстрой саккаде слегка
  растягиваются по горизонтали (до 8 %) — «смаз движения».
- **Дыхание**: синус, масштаб головы ±0.6 % и сдвиг ±3.5 ед. × амплитуда; во сне ×2.4 при 0.15 Гц.
- **Микродвижения**: сумма несоизмеримых синусов 0.17–0.61 Гц: голова x ±2.5, y ±1.8 ед., наклон ±0.7°, брови ±1.
- **Время**: все фазы (микродвижения, дыхание, покачивание «?», капля, «z») копятся по dt с модулем периода, расписание
  (моргания, взгляды, реакции) — целые миллисекунды. Нет «времени во float от аптайма»: через месяц работы киоска лицо
  движется так же, как в первую минуту (тест `face does not depend on uptime`).

### 5.7 Звук → лицо

Источники (`audio/AudioLevels.kt`, читаются кадром без блокировок):

| Что | Откуда | Точность |
|---|---|---|
| голос посетителя: **говорит ли** | VAD: `EnergyVad`/`LiveEndpointer` (`ServerVoiceGateway`), `user_speaking`/`user_partial` → `user_final`/`ignored`/`thinking` (`LiveSession`) | 40–100 мс |
| голос посетителя: громкость | RMS кадров микрофона: `ServerVoiceGateway` и `LiveSession`; шумовой фон вычитается | 40–100 мс |
| речь робота, live | RMS блоков 20 мс PCM, записанных в AudioTrack, **по позиции воспроизведения** (не по записи): `StreamPlayer` → `PcmPlaybackMeter`, позиция экстраполируется по часам | ~20 мс |
| речь робота, MP3 серверного TTS | один `Visualizer` на общей аудиосессии всех клипов (волна ~20 раз/с), создаётся и включается на своём потоке — главный поток на старте фразы в audioserver не ходит — **проверить на роботе** | ~50 мс |
| встроенный TTS робота, Android TTS, субтитры без звука | громкости нет → синтетические слоги 3.5–6/с с паузами между словами | — |

Сглаживание: огибающая с атакой 45 мс и спадом 140 мс (речь) / 40 и 250 мс (микрофон), порог шума, автоусиление
по пику (пик догоняет за 0.25 с, спадает за 2 с, не ниже 0.12 / 0.06) → 0..1. У микрофона — ещё шумовой фон: быстро
опускается в паузах (0.4 с), медленно поднимается (8 с), вычитается с запасом ×1.3 — постоянный гул −30 дБFS даёт 0. Рот — ещё через свою пружину
(ζ 1, response 0.09 с): слог открывает рот за ~25 мс, без рывков. Поверх: ширина рта −10 % при раскрытии,
кивок до 4 ед., брови вздрагивают на ударениях. Голос посетителя: глаза +5 %, брови +9 ед., наклон +1.5°,
свечение +0.15.

### 5.8 Производительность

- В кадре нет аллокаций: Paint/Path/шейдеры созданы заранее, движок — массивы `FloatArray`. Тест
  `FaceEngineTest.frame loop does not allocate` гоняет 5000 кадров по всем занятиям в отдельной JVM и считает
  байты (`ThreadMXBean.getThreadAllocatedBytes`): 288 байт — это сам замер.
- Кадр — по vsync, только фаза отрисовки одного узла; лицо скрыто или приложение не на экране — кадры не
  запрашиваются.
- Когда лицо закрывает экран, прежний экран `INVISIBLE`, фоны окна и корня сняты — одна заливка вместо трёх.
- Анимации — transform/alpha (`graphicsLayer`) и параметры рисования; layout не анимируется.
- Шрифт острова загружается заранее в фоне (первая поездка не читает .ttf на главном потоке).

Замер `dumpsys gfxinfo` на AVD `nova`, ~100 с сценариев (покой, перебивание морфинга, звук, вопрос, реакции,
эмоции, сон/пробуждение, поездка), файлы — `.claude/ui-redesign/shots/M1/gfxinfo_*.txt`:

| Эмулятор | Кадров | Janky (deadline missed) | Slow UI thread | Missed vsync |
|---|---|---|---|---|
| `-gpu host` (Intel UHD, skiagl) | 5823 | **4 (0.07 %)** | 1 | 0 |
| `-gpu swiftshader_indirect` (программный GPU, нагрузка хоста ~17) | 5720 | 231 (4.0 %) | 81 | 44 |
| прежний экран на swiftshader, для сравнения (12 с покоя) | 433 | 251 (58 %) | — | — |

На swiftshader узкое место — растеризация на CPU хоста («slow issue draw commands»), не код приложения:
59 кадров/с держатся, прежний экран на том же эмуляторе даёт ~36 кадров/с. Финальная проверка — на роботе.

## 6. Экран 1

Только лицо на весь экран (`FaceScreen.kt`). Исключения:
- во время поездки — «остров» снизу по центру: «→ Иду к: Кафе» + белая кнопка «Стоп»; появляется
  «материализуясь» (scale 0.92 → 1 + прозрачность, пружина Default, от нижнего края), уходит тем же путём;
  кнопка: scale 0.97 на касание (Press), действие на отпускании;
- ручка свайпа и остров where_is — M2/M4.

Свайп влево (временно, до экрана 2 в M3) — прежний экран с функциями: лицо следует за пальцем с сопротивлением
rubber-band 0.55, решение — по знаку скорости (> 700 px/с) или проекции импульса Apple (d = 0.998) за 25 % ширины
(`SwipeToMenu`, тест). Засчитан — лицо **продолжает движение пальца**: пружина Gentle с начальной скоростью пальца к
точке проекции (не ближе 120 dp), без перелёта назад, и гаснет; не засчитан — Momentum-пружиной на место. Обратно —
тем же путём: «К роботу» или системное «Назад».

Тап по лицу (`FaceInputMapper.tap`, тест): спит — проснуться; говорит — замолчать (тот же путь, что «Стоп» /
`interrupt` в live), кроме поездки — её останавливает только «Стоп» на острове. Свайп тап отменяет (порог касания).
Остальное (моргнуть / удивиться на тап, поглаживание, long press) — M2.

## 7. Отладка на эмуляторе (для проверки)

Только debug-сборка flavor `emulator` (`FaceDebug.kt`, ресивер регистрирует MainActivity). Команда:

```
adb shell am broadcast -a kz.astanahub.robot.DEBUG_FACE -p kz.astanahub.robot --es cmd <команда> [--es arg '<аргумент>']
```

Настоящие события (идут обычным путём через MainViewModel, фейковый бэкенд и заглушки робота):

| cmd | arg | Что происходит |
|---|---|---|
| `ask` | текст | вопрос как с экрана: «думает» → эмоция → «говорит» (рот — синтетические слоги, TTS у фейкового бэкенда нет) → покой. «Проводи в кафе» — поездка 6 с с «препятствием» на полпути → «приехали»; «Где кафе?» — where_is; «Что это?» — снимок |
| `arrive` / `leave` | — | подошёл / ушёл человек (заглушка PersonApi): пробуждение, приветствие |
| `sleep` | — | уснуть сейчас (как по таймеру бездействия): зевок → сон |
| `wake` | — | разбудить (как касание) |
| `stop` | — | «Стоп» (в поездке — реакция ACK) |
| `look` | — | «Что это?» |
| `menu` / `face` | — | прежний экран / к лицу |

Звук (подмешивается в `AudioLevels` — тот же путь, что у настоящего микрофона и плеера):

| cmd | arg | |
|---|---|---|
| `mic` | `on` / `off` | имитация голоса посетителя (VAD + громкость): покой → «слушает», реакция на громкость |
| `noise` | `on` / `off` | гул зала −30 дБFS без речи (VAD молчит): лицо остаётся в покое |
| `play` | `on` / `off` | громкость речи робота (рот в состоянии «говорит») |

Лицо напрямую (для снимков каждого выражения):

| cmd | arg | |
|---|---|---|
| `mood` | `idle`, `listening`, `thinking`, `speaking`, `looking`, `travel`, `happy`, `excited`, `ack`, `confused`, `error`, `surprised`, `petted`, `yawn`, `sleep`, `wake`, `auto` | принудительное состояние (`auto` — снова по событиям) |
| `emotion` | `neutral`, `happy`, `excited`, `surprised`, `sad`, `thinking`, `auto` | принудительная эмоция поверх состояния |
| `cue` | `error`, `confused`, `greet`, `arrived`, `trip_failed`, `trip_cancelled`, `surprise` | реакция (тот же вход, что `MainViewModel.faceCues`) |
